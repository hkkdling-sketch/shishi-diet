# 识食 · 项目工作手册

单文件 PWA（`index.html` 内联全部 CSS/JS，零运行时依赖，数据存 localStorage）。
核心差异点是**按库存记账**：买菜入库一次，之后吃多少扣多少 —— 不是按餐次记录。

本机仓库在 WorkBuddy 会话目录下的 `shishi-diet/`（用 Glob 找 `_build/assemble.py` 即可定位）
线上：<https://hkkdling-sketch.github.io/shishi-diet/>

> 本技能有两份：仓库内 `.workbuddy-ai/skills/shishi-diet/`（随代码走，团队共享）
> 和用户级 `~/.workbuddy-ai/skills/shishi-diet/`（实际生效的那份）。
> **改动请同时更新两处**，否则会漂移。

## 铁律

这些是踩过坑之后定下的，违反会直接导致交付事故。

**1. 绝不手工编辑 `index.html`。** 它是生成物，由 `_build/assemble.py` 拼装。
改代码要改 `_build/` 下的源文件：

| 源文件 | 内容 |
|---|---|
| `_build/new_app.js` | 全部 JS 逻辑 |
| `_build/new.css` | 全部样式 |
| `_build/new_body.html` | HTML 结构 |

改完必须跑：`python _build/assemble.py`（拼装）→ `python _build/verify.py`（结构校验）。

**2. 交付前必须全部测试通过。** 见 `references/testing.md`。当前 **392 条断言 + 浏览器端到端**。
一条不过就不算改完。

**3. 界面里禁止 emoji。** 图标一律内联 SVG（`ICON_PATHS` + `ic(name,size)`）。
emoji 在 iOS / Android / Windows 上渲染差异极大，而且会破坏视觉一致性。
**注释里也别用** —— 校验脚本会扫到。

**4. 不把密钥写进代码或提交进仓库。** 导出备份时 `S.api.key` 必须清空。
仓库是公开的，GitHub 上有机器人专扫 API Key。

**5. 改了 `proxy/worker.js` 要一起验证部署页。** 部署页实时读取该文件，测试会逐字比对。

## 工作流

```
改 _build/ 源文件
  → bash _build/test.sh            # 拼装 + 结构校验 + 9 个断言套件 + 元测试
  → bash _build/test.sh --full     # 再加浏览器端到端（会自己起本地服务）
  → bash _build/push.sh <文件...>   # 推送（走 GitHub Contents API）
  → 等 Pages built，比对线上与本地字节数一致
```

**不要手敲 `node _build/edge-*.js`** —— 这个 glob 会漏掉 `edge3.js`（没有连字符）
和 `test-worker.mjs`（不是 .js）。`test.sh` 里是显式列表，一条不漏。

推送用 `_build/push.sh`（走 GitHub Contents API），**不要用 `git push`** ——
沙箱内 git 传输层被代理阻断，会反复报 `CONNECT tunnel failed`。

## 设计规则

- **数字用 `tabular-nums`** —— 否则数值跳动，纵向对不齐
- **主指标用「条形 + 数字」，不用环形图** —— NN/g：长度是最准的视觉编码，角度/面积最差；
  且 Apple HIG 把 Activity 圆环保留给健康三环，不得挪用
- **不能只靠颜色传达状态** —— 约 4.5% 的人有色觉障碍（男性 8%）。必须有文字标签
- **对比度**：正文 ≥4.5:1，图标/进度条等**非文本元素 ≥3:1**（WCAG 1.4.11）
- **触控目标**：WCAG 2.2 最低 24×24px，Apple 建议 44pt，Google 48dp
- **超出/超标不要用警告红** —— CHI 2015：negative nudge 显著提高弃用率。
  用中性措辞（「已超出」）+ 琥珀色 + 一句「看一周整体趋势更有意义」
- **文案要回答「为什么」**，不只是「怎么做」

## 领域规则

**营养字段以 GB 28050《预包装食品营养标签通则》为准。** 强制标示 7 项：
能量、蛋白质、脂肪、**饱和脂肪**、碳水化合物、**糖**、**钠**。

**「目标项」和「限量项」语义相反，不可混用：**

| | 目标项 | 限量项 |
|---|---|---|
| 有谁 | 热量 / 蛋白 / 脂肪 / 碳水 / 纤维 | 钠 / 饱和脂肪 / 糖 |
| 语义 | **要吃到** | **要压住** |
| 上限 | 按需求计算 | 钠 <2000mg；饱和脂肪与糖各 <总热量 10%（糖另 ≤50g） |

**数据不变式（`edge-adapt.js` 里有断言守着）：**
- 饱和脂肪 ≤ 总脂肪
- 糖 ≤ 碳水
- 宏量回算（`pg*4 + fg*9 + cg*4`）与目标热量偏差 ≤4 kcal

**自适应 TDEE**（`adaptiveTDEE()`）用能量守恒反推：
`TDEE = 日均摄入 − 体重趋势斜率 × 7700`。四个不可省的细节：

1. 体重趋势用**真实天数**做最小二乘，不是数组序号
2. **剔除「漏记」的日子**（没记录、或低于目标 60%）—— 漏记整餐会系统性低估 TDEE
3. **扣掉平均训练量**再叠加当日训练，否则规律训练者被重复计算
4. 结果超出 `[BMR, BMR×2.5]` 就拒绝给出

## 项目已沉淀的判断

写代码前先读这几条，能省掉返工。

**做功能前先查规范。** 前七轮都在优化「我觉得不够好的地方」，
却漏掉了国标强制字段 —— 那不是「还可以更好」，是「本来就不合格」。
规范类信息成本最低、收益最高、且不依赖品味。

**测用户的实际动作，不是测元素的存在性。** 「选图只能选一张」和「只能用相机重拍」
两个 bug 活了七轮，因为测试只断言元素存在，从来没真的选一张图进去跑。
现在用 `page.setInputFiles()` 真跑。

**断言不能同义反复。** 期望值必须来自独立来源（字面量、手算结果、规范），
不能把源码里的公式再抄一遍 —— 那样按构造必然通过，永远不可能和代码不一致。

**「零后端」是卖点也是约束。** 它意味着：没有服务器藏密钥、换设备要重新配置、
照片只在你和模型厂商之间传输。做取舍时要把这条摆上桌，而不是绕过去。

**中餐场景是护城河。** 混合菜肴难分割、同名不同做法、一盘炒青菜能吸 20–30g 油 ——
行业通用的「整菜识别」在中文场景误差极大。而库存记账天然是食材级的，
绕开了整菜识别。这不是「也有个功能」，是结构性差异。
