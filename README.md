# 识食 · AI 饮食管家

> 拍张照就知道吃了多少营养，按「库存」记账而不是按「条目」记账。  
> 单文件 PWA，纯本地存储，离线可用，无需注册登录。

**🌐 在线体验：<https://hkkdling-sketch.github.io/shishi-diet/>**（手机打开后「添加到主屏幕」即可当 App 用）

**📱 第一次用请先看：[手机上怎么用](https://hkkdling-sketch.github.io/shishi-diet/guide/)** —— 从装到桌面到每天怎么记，3 分钟看完。

**🔍 想了解设计依据：[行业调研报告](https://hkkdling-sketch.github.io/shishi-diet/research/)** —— 国标字段规范、无障碍标准、竞品对标、差距清单。

> 改造过程、设计决策与踩坑记录见 [CHANGELOG.md](CHANGELOG.md)。

一个把**冰箱/储物柜库存**当作记账单位的饮食管理工具。区别于市面上所有「搜食物 → 记一笔」的卡路里 App：你先把买回来的食材按克重入库，之后每次吃就从库存里扣减。想撤销记录时，克重会原样退回库存——这让「我这个月到底买了多少肉、还剩多少」变成可查的数据，而不是一笔糊涂账。

**别的 App 记你吃了多少，识食算你还剩多少 —— 还按你练不练，天天换目标。**

---

## 为什么做这个

现有的热量记录 App 都要求你**先搜索、再选份量**，这件事本身就很烦。真实的做饭场景是：昨天买了 1kg 鸡胸肉，今天炒了大概三分之一——你既不知道精确克重，也懒得先查食物库。

所以识食换了个方向：

| 常见做法            | 识食的做法                 |
| --------------- | --------------------- |
| 搜食物 → 选份量 → 记一笔 | 食材**入库**一次，之后吃多少扣多少   |
| 记录是孤立的数字        | 记录与库存**双向联动**，可撤销、可回滚 |
| 强调「今天摄入」        | 额外回答「**存货还剩多少、够吃几天**」 |

## 功能

### 📷 拍照识别营养（可选 AI）

- 对接任意 **OpenAI 兼容**的 `/chat/completions` 接口，**自带 Key（BYOK）**
- 内置四档预设：**智谱 GLM-4V-Flash**（目前免费）、通义千问 Qwen-VL、OpenAI GPT-4o-mini、**自建代理（不用填 Key）**
- 三种模式：**包装食品**（拍配料表 + 营养成分表）/ **生鲜食材** / **外食熟食**
- 按 **GB 28050** 的 7 项强制标示提取（含钠、饱和脂肪、糖）
- **可一次选多张照片**（最多 6 张），配料表 + 营养成分表一起识别更准
- 识别结果**可手动修正**后再入库，不盲信模型
- **有「测试连接」按钮** —— 配好当场验证地址/模型/Key 三者是否都对
- 报错会翻译成人话：网络不通 / Key 不对 / 地址写错 / 频率超限，分别给不同提示
- **不配 Key 也能用**：内置 109 条食物数据 + 手动输入，记账功能完全不受影响

#### 为什么要自己填 Key？（以及怎么免掉）

识食是**零后端**的单文件应用 —— 没有服务器，也就没有地方安全地藏一个共享 Key。
把 Key 写进代码里会被公开仓库的爬虫扫到并盗刷，所以只能由使用者自己提供。

**如果不想每台设备都填一次**，仓库里带了现成方案：把 Key 放到一个免费的
Cloudflare Worker 里（`proxy/` 目录，含完整代码和 5 分钟部署步骤）。

> 📖 部署图文步骤：**<https://hkkdling-sketch.github.io/shishi-diet/proxy/>**（带「复制代码」按钮）
客户端只填代理地址、**Key 留空**，之后所有设备永久免配置。

> 代价：照片会经过你的 Worker 转发。对隐私有要求就继续用直连 + 自己填 Key —— 这是明确的取舍。

### 🥬 库存管家（核心差异点）

**它不是「记库存」，是「算库存」。** 别的 App 告诉你「还剩 620g」，  
识食告诉你「还能吃 6 天，该买鸡胸肉了」。

| 能力            | 说明                                          |
| ------------- | ------------------------------------------- |
| **消耗速度预测**    | 按近 7 天实际消耗算日均，预测每样食材**还能吃几天**；全库还有**多少天续航** |
| **不一定给预测**    | 有记录的不足 2 天时显示「待记录」而**不硬算**——宁可说不知道，也不给噪声数字  |
| **自动采购清单**    | 按真实消耗速度，把低量食材补足到够吃 7 天，一键生成、可复制             |
| **今日缺口分析**    | 对比目标与已摄入，列出还差多少热量 / 蛋白 / 脂肪                 |
| **蛋白补足建议**    | 从**你的库存里**按蛋白密度挑最优食材 → `吃 1400g 希腊酸奶 可补足蛋白` |
| **每项自定义提醒线**  | 鸡蛋剩 25g 该买、巴旦木剩 60g 不用买——一个全局阈值管不了          |
| **14 天消耗柱图**  | 点开任一食材看它的真实消耗曲线                             |
| **批量补货 / 清空** | 不用一个个点                                      |
| **今日页提醒钩子**   | 不去库存页也能看到「该补货了」                             |

基础记账能力：

- 按克重入库，自动折算总营养；按分类分组（肉蛋奶 / 主食 / 蔬菜 / 水果 / 油脂 / 其他）
- 吃掉时一键扣减，支持常用份量快捷键
- 删除记录 → **克重原样退回库存**；若该食材已被吃光移除，会连同营养数据一起重建
- 手动输入或 AI 识别出的新食材，自动**推断分类**（精确匹配 → 部分匹配 → 关键词正则）

### 📊 个人目标与计算

- 基于 **Mifflin-St Jeor** 公式算 BMR / TDEE（营养学界主流，比 Harris-Benedict 更准）
- 活动系数 5 档 × 目标调整 5 档
- 蛋白质按 g/kg 体重设定，**自动封顶在总热量 35%**（超过这个比例没有额外增肌收益，反而挤占碳水）
- 脂肪**兜底不低于 0.5g/kg**（必需脂肪酸下限）
- 总热量**不低于 BMR×1.1**，避免极端节食
- 碳水 = 剩余热量，保证宏量营养素回算误差 ≤ 4 kcal
- **训练日 / 休息日两套目标**：训练日 = `TDEE + 实际运动消耗`，休息日 = `TDEE + 自定义调整`；蛋白质按当日强度上调（低 +0.1 / 中 +0.2 / 高 +0.4 g/kg），碳水按 g/kg 分档参考，脂肪取总热量的 28%（训练日）/ 30%（休息日），碳水补足余量 → 宏量营养素**永远回算等于目标**
- **膳食纤维**独立成项（IOM 标准：男 <50 岁 38g、≥50 岁 30g；女 <50 岁 25g、≥50 岁 21g），**训练日 +5g**

### 📈 习惯与趋势

- **连续记录天数**：今天还没记不算断（当天未结束），另显示本月天数与历史最长连续
- **体重趋势**：用**最小二乘拟合斜率**，输出 kg/周——看趋势，不看单日波动
- 少于 2 个数据点时**不给趋势**，只提示「记录体重」，不拿单点瞎画线
- 同一天改多次体重只保留最后一次，避免污染趋势线
- 折线图为内联 SVG，无图表库依赖

### 🏃 训练消耗（自由输入，不是固定菜单）

**别的 App 让你从 20 个固定项目里挑一个；识食让你直接填「跑了 5 公里，用时 30 分钟」。**

| 输入方式        | 适用                      | 算法                                  |
| ----------- | ----------------------- | ----------------------------------- |
| **距离法**     | 跑步 / 快走 / 骑行 / 游泳 / 划船机 | `kcal = 1.036 × 体重(kg) × 距离(km)`    |
| **时长法**     | 跳绳、力量、球类等 18 项          | `MET × 体重 × 小时`                     |
| **心率法**（可选） | 任何有氧                    | Keytel 公式，按平均心率算 kcal/min，比 MET 更贴身 |

- 距离法**不看你跑多快**：同样 5 公里，25 分钟和 40 分钟消耗**几乎一样**——这是运动生理学的既定结论（单位距离的能量成本相对恒定），也是选距离输入而不是配速输入的理由
- 填了平均心率就自动升级为心率法，并给出**心率区间**（用 Tanaka 公式 `208 − 0.7×年龄` 算最大心率，比老式 `220 − 年龄` 更准）
- 支持**自定义动作**：自己的动作库，命名 + MET 值，永久保存
- 消耗**实时叠加进当日目标**，不是躺着的一个装饰数字

### 🗓 训练日程日历

- 月历视图，**每天单独设定**：今天练不练、练什么、多远 / 多久、什么强度档
- 训练日 / 休息日 / 已记录 三种状态在日历上直接可见
- 排好的日程可**一键带入**记训练抽屉，不用重复填
- 强度档（低 / 中 / 高）会同时影响**当日热量目标、蛋白质克数、碳水档位**

### 🍽 实时「还差多少」

- 目标 − 已吃 = **实时剩余**，热量 / 蛋白质 / 碳水 / 脂肪 / 膳食纤维 五项同时显示
- 吃超了不显示 0，而是显示 **「已超出 X」**（负数是有信息的，不该被吞掉）
- 从**你自己的库存**里挑最优食材给出补足建议：`吃 650g 鸡胸肉(生) 可补足蛋白`，一键去记录
- 打分 = `营养密度 / (1 + 热量代价/80) + 分类加成`，热量代价 = `该食材每克目标营养对应多少 kcal`

### ⚖️ 限量项：钠 / 饱和脂肪 / 糖

按 **GB 28050《预包装食品营养标签通则》** 的强制标示项追踪。语义和「目标项」相反 —— 那三项要吃够，这三项要压住：

| 项目 | 上限 | 依据 |
|---|---|---|
| 钠 | 2000 mg | 国标 NRV，也是 WHO 推荐上限 |
| 饱和脂肪 | 总热量的 10% | 中国居民膳食指南 |
| 糖 | 总热量的 10%，且 ≤50g | 中国居民膳食指南（添加糖 <25g 更佳） |

- 今日页有独立的「今日限量」卡，条形朝上限填充，超标时用琥珀色 + 「已超出 X」
- 109 条食物库全部含 `na` / `sf` / `sg` 字段
- 拍照识别按国标 7 项提取（包装食品模式下模型会一并给出钠、饱和脂肪、糖）

### 🧭 自适应 TDEE（实验）

不用公式估算消耗，而是**用能量守恒反推**：

```
摄入 − 消耗 = 身体储存的能量变化
→ TDEE = 日均摄入 − 体重趋势斜率 × 7700 kcal/kg
```

- 需要 **14 天饮食记录 + 跨度 14 天以上的体重记录**才开始启用；数据不足时明确显示还差多少，不硬算
- **必须剔除「漏记」的日子** —— 漏记整餐会系统性低估 TDEE（以为你吃得少 → 推出消耗也低 → 目标越调越低）。识食会把「没记录」和「低于目标 60%」的日子排除，并告诉你剔除了几天
- **扣除平均训练量**再叠加当日训练，避免规律训练的人被重复计算
- 结果超出合理范围（BMR ~ BMR×2.5）时**拒绝给出**，并说明「多半是记录不全」
- 体重趋势用**真实天数**做最小二乘，不是数组序号

> 为什么识食特别适合做这个：它需要「精确摄入」+「连续体重」两个输入。多数 App 缺的是前者 —— 搜食物选份量本身误差就大；而按克扣库存的记账方式，摄入精度天然高一个量级。

### 🍜 外食拍照记账

- 在外面吃、不是从库存拿的 → 拍照走 **「外食 / 熟食」** 模式，**不扣库存**
- 也可以**全屏手填**：名称 / 克重 / 热量 / 蛋白质 / 碳水 / 脂肪 / 纤维 / 钠 / 饱和脂肪 / 糖
- 今日列表里外食条目带 **「外食」** 标记，一眼区分「吃库存」和「外面买的」
- 相册可**一次选多张**（最多 6 张），缩略图可逐张删除 —— 拍配料表 + 营养成分表一起识别更准

### 💾 数据

- 全部存 `localStorage`，**不上传任何服务器**
- 一键导出 / 导入 JSON 备份
- 数据 schema 带版本号（`shishi_v2`），旧版本数据自动迁移

### 📲 装到手机桌面

**没有安装包、不上架应用商店**——识食是网页应用（PWA），「安装」= 用浏览器打开 + 添加到主屏幕。

- **安卓 Chrome / Edge**：首页横幅点一下就弹**系统原生安装框**（捕获 `beforeinstallprompt`），不用翻浏览器菜单
- **iOS Safari**：没有一键安装 API，给**图文步骤**（分享按钮 → 添加到主屏幕）
- **其它浏览器**：给「去菜单里找」的指引，并建议换 Chrome
- 已在桌面图标里打开时**整块隐藏**，不再打扰；首页那条可以点 × 关掉，**「我的」页始终保留入口**

## 快速开始

### 直接用

1. 下载 `index.html`、`manifest.json`、`sw.js`、两个 `icon-*.png` 到同一目录
2. 用浏览器打开 `index.html`
3. **手机上**：用浏览器打开在线地址 → 首页横幅点「去安装」（安卓一键弹系统框）/ 分享菜单「添加到主屏幕」（iOS）

> 📱 手机上装的完整说明（iPhone / 安卓对照 + 10 条 FAQ）见 **[手机上怎么用](https://hkkdling-sketch.github.io/shishi-diet/guide/)**。

> ⚠️ 必须通过 `http://` 或 `https://` 访问才能启用 Service Worker（离线能力）和**安装能力**。直接双击 `file://` 打开也能用，但没有离线缓存、也装不了。

本地起个服务：

```bash
python -m http.server 8000
# 然后访问 http://localhost:8000
```

### 启用 AI 拍照识别（可选）

1. 打开 **拍照** 页 → 展开「识别接口设置」
2. 服务商选 **智谱 GLM-4V-Flash**（免费，国内可直连，无需梯子）
3. 去 [bigmodel.cn](https://open.bigmodel.cn/) 注册 → 创建 API Key → 填进去
4. 保存后即可拍照识别

Key 只存本机 `localStorage`，不会上传到任何地方。

## 开发与测试

本项目带一套**零依赖**的自动化校验（只用 Python 标准库 + Node）：

```bash
# 构建：把分段源文件拼回单文件（改完源文件必须跑）
python _build/assemble.py

# 结构校验：标签配对、必需函数、边界保护标记、emoji 残留
python _build/verify.py

# 运行时冒烟：最小 DOM stub 跑 boot / calc / 渲染全流程
node _build/smoke.js

# 边界用例：极端减脂、高蛋白封顶、库存闭环、撤销回滚
node _build/edge3.js

# 库存管家：消耗预测、采购清单、缺口分析、分类推断（35 条断言）
node _build/edge-inv.js

# 撤销回滚：精确还原、吃光重建、跨日期退款（6 场景）
node _build/edge-undo.js

# 习惯层：连续天数、月度统计、体重趋势斜率（28 条断言）
node _build/edge-habit.js

# 训练层：距离法/心率法/MET、训练日判定、双套营养目标、
```

### AI 协作约定

仓库里的 `.workbuddy-ai/skills/shishi-diet/` 是一份**项目技能**，把构建流程、测试纪律、设计铁律和领域规则写成了可被 AI 直接加载的形式。

它解决的问题：这个项目积累了大量「不写下来就会踩第二次」的约定 ——不能手改 `index.html`、界面禁止 emoji、限量项和目标项语义相反、断言不能同义反复、测用户的实际动作而不是测元素存在性。

任何 AI 会话加载它之后，就不用再从零解释一遍这些规则。

**文档漂移由 `_build/verify-skill.js` 守着** —— 它会静态统计各套件的断言数，
和技能文档里写的数字逐条对账，同时校验两份技能逐字一致。
（这条守卫是被真实事故逼出来的：加了一条断言后忘了改技能，技能里写着 359、实际 360。）


全部通过才算改动合格。当前合计 **360 条断言 + 浏览器端到端选图测试**。覆盖的关键断言：

- 宏量营养素回算热量与目标偏差 **≤ 4 kcal**（训练日与休息日都要过）
- 蛋白质占比 **≤ 35%** 总热量
- 脂肪 **≥ 0.5 g/kg** 体重
- 总热量 **≥ BMR × 1.1**
- 库存「吃掉 → 撤销」克重**精确还原**（含已吃光条目的重建）
- 消耗预测在**样本不足 2 天时返回 null**（不给噪声预测）
- 采购清单**只含低量项**，且告急项排前
- **同样 5 公里，25 分钟与 40 分钟消耗完全相同**（距离法的核心性质）
- 70kg 跑 5km → **363 kcal**（对得上公开跑量计算器）
- 心率法的零点：男 ~57 bpm / 女 ~63 bpm 以下钳制为 0，不出负消耗
- 训练日目标 **>** 休息日目标；强度越高蛋白质越高
- 膳食纤维：训练日比休息日**多 5g**；年龄 ≥50 岁切到更低档
- 吃超时缺口返回**负数**（供「超 X」展示），不是钳成 0
- 外食记录**不动库存**；同名库存项扣减时**正确扣减**
- 自定义动作 MET 必须落在 1–25，重名被拒
- 训练记录：距离型不填距离、时长型不填时长 → 拒绝；`km ≤ 500`、`min ≤ 900`、心率 60–230
- `S.plan` / `S.ex` 被外部改成 `null` 或数组时**不崩**（防御性归一化）
- 安装：已在桌面运行时**整块隐藏**；`beforeinstallprompt` 被 `preventDefault` 拦下；
  iOS 走图文步骤**不给一键按钮**；iPadOS（伪装成 Macintosh）也能识别；真正的 Mac 不误判
- 安装：「以后再说」只关首页横幅，**「我的」页入口仍在**，且持久化到 `localStorage`
- 安装：一个 `beforeinstallprompt` **只能 prompt 一次**，重复点击不重复弹
- 钠上限固定 2000mg；饱和脂肪/糖各取总热量 10%，糖另有 50g 硬上限
- 食物库 109 条全部含 `na`/`sf`/`sg`，且**饱和脂肪 ≤ 总脂肪、糖 ≤ 碳水**
- 自适应 TDEE：吃 2000 / 掉 1kg/14 天 → 反推 **2551 kcal**（理论值 2550）
- 自适应 TDEE：**漏记整餐的日子必须被剔除**，否则 TDEE 会被系统性低估
- 自适应 TDEE：扣除平均训练量，避免规律训练者被重复计算
- 自适应 TDEE：结果超出 BMR~BMR×2.5 时**拒绝给出**
- 体重趋势用**真实天数**（旧实现用数组序号，连记一周再停三周会放大 10 倍）
- 接口配置：`sk-` 开头的 Key **不猜服务商**（OpenAI/通义都可能）；已有地址时**不覆盖用户配置**
- 接口配置：地址为空但 Key 是智谱格式 → 自动补地址；认不出时**不瞎填**
- 接口配置：**无 Key 模式不再误报「先填 API Key」**；报错信息按 401/404/429/网络错误分别翻译
- 代码里**不得使用浏览器专有的全局 `event`**（非浏览器环境会 ReferenceError）
- 代理 Worker：**陌生来源必须被 403 拦住**（这是防白嫖的唯一屏障）
- 代理 Worker：**上游 401/错误必须原样透传**，且错误响应也要带 CORS 头（否则前端读不到）
- 代理 Worker：模型白名单外的模型必须被拒，防止拿你的 Key 跑贵模型
- 代理部署页展示的代码必须与 `proxy/worker.js` **逐字一致**（页面实时读取，不会过期）
- 无原生 `alert` / `confirm` / `prompt` 调用
- 正文对比度：浅色 ≥ 4.5:1、深色 ≥ 7:1；390px 视口零横向溢出
- **库存概览卡与缺口分析卡必须在首屏内**（防止关键信息被挤下去）
- 体重趋势在**少于 2 个数据点时返回 null**（不拿单点瞎画趋势线）
- 体重平台期斜率为 **0**（不是 null，也不除零）
- 连续记录：**今天还没记不算断**；空数组不算「已记录」

> ⚠️ DOM stub 测试不能替代真实浏览器。曾经有个「首屏空白」的 bug，  
> 在 stub 里所有断言都是绿的（元素存在、内容非空），只有 Playwright 截图才发现  
> 父容器 `display:none`。所以 `render.js` 是必跑项。

## 数据来源

食物营养数据基于《中国食物成分表》整理，共 109 条（含膳食纤维 `fb`、钠 `na`、饱和脂肪 `sf`、糖 `sg`）。运动 MET 值参考 *Compendium of Physical Activities*；心率消耗用 Keytel et al. (2005) 公式；最大心率用 Tanaka 公式；膳食纤维推荐量用 IOM 标准；跑步单位距离消耗系数取 `1.036 kcal/kg·km`。

**营养数据为估算，仅供参考，不构成医疗建议。**

## 已知限制

- 食物库 109 条，覆盖常见食材但远不完整；欢迎按 `FOODS` 数组格式补充
- AI 识别精度取决于模型，包装食品的配料表拍摄角度影响很大——所以识别结果**一定要人工核对**
- 距离法只对「位移类」有效；力量训练、球类仍走 MET，个体差异较大
- 心率法需要你手动填平均心率，没有手表同步（**不申请任何健康数据权限**）
- 数据存 `localStorage`，**清理浏览器数据会丢失**，请定期导出备份
- 换设备需手动导出 / 导入 JSON
